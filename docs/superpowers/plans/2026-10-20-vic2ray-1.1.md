# Vic2Ray 1.1 Implementation Plan

> **For agentic workers:** Use executing-plans for the integration work and delegate the independent UI, core and delivery tasks in parallel. Track progress here; the owner explicitly delegates design, execution and GitHub release decisions.

**Goal:** Ship a more usable and reliable Vic2Ray Android app with tested, signed GitHub releases.

**Architecture:** Preserve native Compose and the bundled Xray AAR. Keep presentation, catalog/persistence, core lifecycle and delivery code separate, with explicit StateFlow contracts.

**Tech Stack:** Kotlin 1.8, Compose BOM 2023.03.00, coroutines, Gradle 8.14.5, AGP 8.13.2, JDK 21.

**Spec:** `docs/superpowers/specs/2026-10-20-vic2ray-1.1-design.md`

## Global Constraints

- Version 1.1.0/code 22; API 24 minimum; API 35 compile/target; JDK 21.
- Preserve `gradle.properties` user edits and bundled custom TUN core integration.
- Secrets stay outside Git; imported links and cached servers survive refresh failures.
- UI text supports Persian/English and Persian RTL. Version text comes from BuildConfig.
- Existing local credentials may authorize requested GitHub operations; never print them.

## Review Focus

- Disconnect while connect/core startup is pending must leave no tunnel, stale ping or connected state.
- A failed or empty subscription refresh must retain imported and previously cached servers.
- Non-ASCII names, escaped passwords, IPv6 and URL-safe Base64 must remain intact.
- GitHub release retries and duplicate tag/push events must not move an existing tag to another commit.
- Large lists, large text, Persian RTL and offline launch must preserve usable controls.

## Task 1: Catalog and persistence (root)

**Files:** `ui/MainViewModel.kt`, new `models/ServerCatalog.kt`, JVM catalog tests.

**Interfaces:** StateFlow properties `allConfigs`, `visibleConfigs`, `searchQuery`, nullable `selectedProtocol`, `sortOrder` (`ServerSort.LATENCY/NAME`), `favorites` (raw-link set), `favoritesOnly`, `lastSyncTime`, `customSources`, `sourceFailures`, `language` (`fa`/`en`), and `uiState`. Actions `setSearchQuery`, `setProtocolFilter`, `setSortOrder`, `toggleFavorite`, `setFavoritesOnly`, `setLanguage`, `importConfigs(text): Int`, `addCustomSource(url): Boolean`, `removeSource`, `restoreDefaultSources`, `syncAndTestServers`, `stopSync`. `UiState.Testing(testedCount,totalConfigs,currentWorking)` reports all completed tests. `ConfigFetcher.fetchSources` returns raw lines and failed source URLs. Tester callbacks report every result.

- [ ] Write and run failing behavior tests for combined search/protocol/favorite filtering, sorting untested servers last, source validation, stable merge and import/cache preservation.
- [ ] Implement pure catalog operations and ViewModel persistence/refresh cancellation using these operations.
- [ ] Run catalog tests and unit suite; review persistence and refresh failure paths.

## Task 2: Core reliability (core worker)

**Files:** `parser/*`, `fetcher/*`, `tester/*`, `vpn/*`, `utils/AssetsUtils.kt`, associated tests.

**Interfaces:** Preserve `generateJsonConfig(rawConfig,protocol,forTest=false)` with optional `socksPort` argument. Service exposes existing `isConnected`, `currentPing`, `connectedRawConfig` plus `isConnecting: StateFlow<Boolean>`, `lastError: StateFlow<String?>`, `connectedSince: StateFlow<Long>`. Keep action and extra names. `fetchSources(sources): FetchResult(rawLines,failedSources)`, compatibility wrapper optional. `testAllStreaming` invokes callback for every completed config on Main.

- [ ] Reproduce parsing, malformed config, insecure TLS and port-substitution defects with focused tests where practical.
- [ ] Implement bounded/cancelable fetch, precise HTTP latency and validated parsing/config generation.
- [ ] Implement serialized service lifecycle and foreground notification with disconnect action; retain real TUN FD.
- [ ] Verify relevant unit tests and Android compilation; document device-only checks.

## Task 3: Dashboard (UI worker)

**Files:** `ui/MainActivity.kt`, additional `ui` presentation files, resources.

**Interfaces:** Consume Task 1 StateFlows/actions and Task 2 service flows. Generate JSON at connection time with `V2rayConfigGenerator`; launch VPN consent then ContextCompat.startForegroundService. Use file picker and share intents for import/export; keep sensitive links out of logs.

- [ ] Implement cohesive dashboard, connection hero, accurate progress, search/filter/sort/favorites and stable keyed server list.
- [ ] Implement source, import and about dialogs, file/clipboard import, sharing, language persistence and RTL.
- [ ] Check compilation and accessibility labels; ensure long lists and small screens can scroll.

## Task 4: Delivery (delivery worker)

**Files:** Gradle build config, `version.properties`, `.github/workflows`, signing ignores, delivery scripts.

- [ ] Configure shared version, JDK 21, SDK 35, test dependencies, stable signing via environment and descriptive APK names. Preserve `gradle.properties`.
- [ ] Add CI validation and release workflow with tests/lint/build, tag agreement, checksums and least permissions.
- [ ] Provision a temporary local Android SDK/JDK setup for verification without committing machine paths.
- [ ] Validate workflow/scripts and produce successful unit/lint/APK builds or concrete environment errors.

## Task 5: Integration, review and release (root)

- [ ] Integrate worker changes, resolve compile/runtime contract issues and update README/changelog.
- [ ] Run `./gradlew testDebugUnitTest lintDebug assembleDebug assembleRelease` with signing configured, inspect package/version/signature and obtain independent code review.
- [ ] Commit only intended files, preserving user modifications. Provision stable signing secrets and push validated code to main; publish v1.1.0 through workflow.
- [ ] Inspect GitHub Actions completion and release APK/checksum assets. Report exact release URL and remaining device verification limits.
