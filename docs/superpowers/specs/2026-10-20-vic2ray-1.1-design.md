# Vic2Ray 1.1 design

The owner requests an autonomous, complete improvement of the existing Android VPN client: understand its implementation, improve everyday usability and animation, and build and publish versioned Android packages on GitHub. Implementation and release decisions are delegated to the agent. Preserve the owner's existing `gradle.properties` edit.

## Product direction

Keep the native Kotlin/Compose application and bundled Xray core. Prefer reliable connection handling and useful server management over adding unrelated services. Deliver version **1.1.0**, Android version code **22**, preserving Android 7/API 24 support. Use JDK 21 consistently, AGP 8.13.2 and Gradle 8.14.5; compile/target API 35 with the required foreground service declarations. Do not claim a SOCKS latency check proves all device traffic traverses the TUN.

## Dashboard and server management

Create a coherent navy, gold and mint dashboard with subtle connection/progress/list animations, clear connecting/connected/error states and no fake connection statistics. Provide Persian and English copy, RTL layout for Persian, a persisted language choice, accessible icon labels, scalable text and scrollable compact-screen layouts. Display the actual BuildConfig version.

Provide fastest-tested-server quick connect, server search, all/protocol filters, latency/name sorting, persisted favorites and a favorites-only filter. Allow importing pasted/clipboard configurations and text files, and sharing individual configuration links with Android's share sheet. Imported links remain available after refresh even before successful testing. Keep cached servers visible throughout refresh, cancellation and network failure. Save successful results in batches rather than serializing the entire list per server.

Source management accepts only valid HTTPS URLs, prevents duplicates and supports restoring defaults. Surface failed sources alongside usable cached results. Track completed tests separately from working servers and record the last completed sync time. Keep refresh and connection work cancelable and bounded.

## Connection and parsing reliability

Retain the bundled core's custom TUN integration and real file descriptor handoff. Serialize connect/disconnect operations; cancel ping and connection work on teardown; require a non-null established interface before reporting connected; publish actionable errors. Start a proper foreground VPN service with a persistent notification and disconnect action. The UI must distinguish starting the core from a successful latency measurement.

Disconnect HTTP connections reliably, reject captive-portal redirects/non-204 responses, use monotonic latency measurement and propagate cancellation. Allocate test SOCKS ports through a typed JSON configuration parameter rather than replacing arbitrary credential strings. Parse and deduplicate supported subscription links consistently, including URL-safe Base64, escaped credentials, IPv6 Shadowsocks endpoints and passwords containing colons. Reject malformed or unsupported formats before starting the core. Verify TLS certificates by default and honor only explicitly requested insecure settings.

## Build and delivery

Use one `version.properties` source for versionCode/versionName, APK filenames, release tags and displayed version. CI runs tests, lint and Android builds for pull requests, main pushes and manual runs. Publish a release on a new main-branch version or matching version tag, using the exact validated commit. Do not depend on a tag pushed by GITHUB_TOKEN triggering another workflow.

Distribute a stable-key signed release APK, a debug CI artifact and SHA-256 checksums. Store signing material only in ignored local storage and GitHub Actions secrets; never commit secrets. Verify tag/version agreement and fail publication if signing credentials are incomplete. Use minimal workflow token permissions and serialize release publication. Document source trust, routing behavior, testing limitations, build commands and signing/release operations accurately.

## Verification

Add JVM regression tests for server filtering/ordering, source validation, import deduplication and core parsing/config generation where practical. Run the Android unit suite, lint and assemble tasks. Inspect the resulting APK metadata/signature and review changes independently. Publish only after checks pass. Exercise connection consent, TUN data flow, reconnect, background survival and screen-reader/RTL behavior on a real Android device when one is available; report any unavailable checks explicitly.
